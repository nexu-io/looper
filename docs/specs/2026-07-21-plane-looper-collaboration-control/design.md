# OPEND-1645 · Looper 多角色协作面板 · 设计 Spec

## 设计目标

把复杂的自动化生命周期翻译成团队成员一眼能懂的协作界面。它首先是“谁在处理、卡在哪里、现在谁行动”的产品界面，其次才是运行监控。

## 信息层级

1. **第一眼**：当前阶段、归属 owner、是否在线、唯一主行动。
2. **第二眼**：产品/设计/研发/QA 中谁在等待、问题数与截止动作。
3. **第三眼**：Spec、PR、验收、最近三条里程碑。

## self-dispatch 弹窗

- 标题：`交给 Looper`
- V1 不选择 owner 或 Node；只展示当前登录用户唯一绑定的 Looper，强调“任务将在你的电脑上运行”。
- 身份摘要包含：头像、owner 名、Node 名、在线/离线、支持角色、当前负载；本人无 active Node 时不打开弹窗，直接给出绑定指引。
- 执行方式默认 `自动判断（推荐）`；`直接实现` 不满足门槛时置灰并在原位解释。
- 底部用自然语言回显实际结果，确认按钮使用 `确认交给我的 Looper`，避免泛化的“确定”。

## 多角色列表

- 产品、设计、研发、QA 使用 Plane 原生的分隔行列表，不再做 2×2 彩色卡片。
- 每行包含 3px 辅助色标记、角色、负责人、职责摘要和文字状态；颜色只做辅助手段，满足色弱可读性。
- 设计问题若有可视方案，在当前行动区提供 HTML 方案与截图入口，不在角色行里堆叠缩略图。

## 状态视觉

- 当前：Plane 品牌蓝实心圆点；在线状态使用绿色小圆点并同时显示文字，不增加装饰性呼吸动画。
- 等待人：琥珀背景，不用红色制造故障感。
- 失败：红色，但主文案直接写可行动原因。
- 完成：绿色勾选。
- 跳过：灰色虚线 + `已跳过` 标签，并显示原因 tooltip。
- 实时信息超过两次心跳未更新：改为灰色 `状态可能过期`，不把任务自动判失败。

## Viewer × lifecycle 风险状态矩阵

| 状态 | owner 看到的主行动 | 其他成员看到的主行动 | 必须直说的风险 |
|---|---|---|---|
| 未派发、本人有 Node | `交给我的 Looper` | 若本人也有 Node，同样只能派给自己；否则只读 | 任务在点击者自己的电脑运行 |
| 本人无 Node / 无编辑权 | `绑定 Looper` 或权限说明 | 同左 | 不能选择或启动同事的 Node |
| 离线且队列关闭 | `Looper 离线`（禁用） | 只读 | 默认不排队 |
| 离线且 owner 已开启队列 | `离线排队` | 只读 | 联网后自动开始 |
| running | 状态 badge + `请求停止` 次操作 | 状态 badge，只读 | 请求停止不等于远程强杀 |
| awaiting human | `查看当前问题` | 仅被映射角色可回答，其余只读 | 回答位置在 Plane，飞书仅通知 |
| projection/role drift | `恢复显示字段` 或 `联系管理员修角色` | 只读 | Authority 未改变；角色 drift 时停止新 run |
| stop requested / revocation pending | `去本地停止并确认` | 只读 | 旧进程和外部副作用可能仍存在 |
| Node 丢失 | `等待 Looper 恢复` | 只读 | V1 不接管、不改派、不强制释放 |
| 409 并发冲突 | `查看当前归属` | 同左 | 已有唯一 owner 生效 |

状态 badge 与 CTA 必须是不同控件：`处理中`、`等待设计`、`等待恢复` 都不可伪装成可点击主按钮。面板同时显示 dispatcher/owner、Authority revision、数据最后更新时间；只有 owner 能看到本地 dashboard 入口。停止/释放确认文案必须提示检查旧 worktree、未提交改动和直接外部副作用。

## 响应式

- `>=1280px`：保留 Plane workspace sidebar、横向阶段轨迹和右侧属性栏。
- `1024–1279px`：属性栏移到正文下方，阶段轨迹保持横向。
- `<1024px`：隐藏 workspace sidebar，保留 breadcrumb header。
- `<768px`：阶段轨迹转为纵向，当前行动按钮与角色行自然换行；不制造独立移动端视觉体系。

## 可用性与无障碍

- 所有状态图标有文字标签；在线状态不只依赖颜色。
- 键盘可完成打开弹窗、确认 self-dispatch 和取消。
- 危险的停止/释放必须二次确认并填写原因；焦点默认不落在危险按钮。
- loading 使用 skeleton，保留面板高度，避免 work item 阅读位置跳动。
- 错误信息就地显示，并保留用户选择用于重试。
