# Agent 交付与验收

协作 Agent 和普通 Worker（含 PR 续跑）收到统一的交付指引，加载公司 `core/skills` 中的 `task-delivery`。Skill 负责按任务选择产物、使用项目真实检查验证需求、生成可交给其他 Agent 的验收指南，并把检测结果和产物关联原 Plane 任务。仓库选择仍由 Agent 完成。

## 安装

从 `core/skills` 取得 `skills/task-delivery`，按该仓库的安装方式安装到执行 Looper 的同一系统用户的技能目录。宿主发现之外，提示也给出 `~/.agents/skills/task-delivery/SKILL.md` 和 `~/.codex/skills/task-delivery/SKILL.md` 作为读取入口。不能只装在发起人的另一台机器上；不会从云端隐式下载或执行 Skill。缺失时 Agent 应说明缺失并按提示准备交付，不能声称脚本已运行。

## 检测与状态

Skill 包含 Python 3 标准库脚本 `scripts/check_delivery.py`，检查空产物、占位文件、版本证据哈希、缺失用例/复核、失败或未执行声明。脚本不执行任意 manifest 命令，也不替代真实功能用例或人类验收。功能结论的 authority 是 Agent 依据原需求、实际运行和复核上报的结构化结果；基础设施不会从文件大小/HTTP 200 推断产品成功。

原生协作继续使用现有 Outcome：

- `links`：验收指南、检测报告、共享预览/产物和各仓 PR。
- `events`：本版本检测/交付事实，包含准确版本、结果和证据链接；失败也记录。
- `context` / `nextStep`：有效版本、剩余工作和实际验收状态。

这些字段通过现有带签名的任务上下文链路回到原 Plane 任务；事件在失败/重启后继续重试。指南和报告可先用现有 Plane CLI 附件或 Page 能力归档并回读确认，再在原飞书话题通知。网络失败要明确待归档，不能将本地 JSON 或飞书消息当作已归档证明。人的反馈正文继续留在源平台。

本改动不新增表、执行器、验收状态机或自动 Done；也不是拒绝任何不合规 Agent 输出的宿主强制拦截器。Skill 的功能验证仍依赖真实用例和执行者如实报告，需要独立验收的任务应交给指定人或其 Agent。部署此版本与在执行用户下安装 Skill 后，新任务及后续会话才有这份提示；已有会话还需在续跑时读取当前指引。

## 网页内容的共享方式

网页类交付默认是飞书文档中的自包含 HTML 附件和真实截图/录屏，不为验收开启本机公网隧道或发布外部网页。只有已有测试环境发布才提供在线页面，注明版本和权限。附件需核对下载内容；无法直接预览时说明下载后打开。依赖后端的功能注明运行条件与未验项，离线 HTML 和截图不代替完整交互验收。飞书文档、附件继续关联原 Plane 任务。

## Pi 长任务的活动与结果

Pi 默认使用已有的 `--mode json` 事件流，工具启动等真实输出进入原有活动计时；结果只解析 `message_end` 的 assistant 文本，工具输出、用户消息、未完成 delta 不作为完成结论。进度摘要过滤完成标记，不把原始 JSON 放进人类可见的活动尾部。显式设置 `--mode text` 会继续保留，但其 print 模式可能直到结束才输出，长任务应使用 JSON；没有启用 Pi 原生 resume 能力。协议依据本机 Pi 1.5.2 的官方 `docs/json.md` 和实际事件流核对。
